# 2026-09-03 — round 3: flyte 2.7.0 + public metrics plugin

## Context

`flyte==2.7.0` and `flyteplugins-union==0.10.0` released — the Metrics
interface is now public (no more private `niels/get-metrics` branch).
Also new: an `LLM_SERVICE_API_KEY` cluster secret in this project, so the
teacher apps are reachable through their **public** endpoints with a
bearer token (the svc-DNS path had proven fragile — it vanishes entirely
when the platform unassigns an idle app).

Round question: does everything still work on the new stack, do pod
metrics flow into eval reports, and can the teacher generate the RL task
dataset through the authenticated public endpoint?

## Upgrade notes / findings before any run

- **`flyteplugins-union` 0.10.0 still declares `flyte<2.7.0` on PyPI** —
  the released pair conflicts by metadata. Worked around with a uv
  `override-dependencies = ["flyte>=2.7.0,<2.8.0"]` locally and a
  re-pin image layer after the plugin layer (see `shared/images.py`).
  Drop both once a plugins release declares 2.7 support.
- The released API surface matches the branch for everything this repo
  uses (`Metrics`, `MetricResult`, `MetricSeries`,
  `Metrics.get_for_action.aio`); `METRIC_NAMES` is no longer re-exported
  from `flyteplugins.union.remote` (we never imported it). 0.10.0 also
  ships a much larger remote surface (ApiKey, Cluster, SSHDebug, …) and
  correspondingly heavier deps (kubernetes, textual, httpx) — reason to
  keep the plugin out of the harness image.
- All 96 unit tests pass on flyte 2.7.0; all deploy units import; all
  three images rebuilt cleanly under the remote builder.
- Teacher auth: `llm_client` now prefers the public endpoint with
  `Authorization: Bearer $LLM_SERVICE_API_KEY` (mounted on `rt-driver`
  from the project-scoped secret), falling back to svc DNS keyless.
  Auth-shaped failures (non-JSON gateway redirect) fail fast instead of
  polling out the ready deadline. `RT_GH_TOKEN` is fully retired.

## The Cloudflare finding

The "stuck at waking teacher while the app is Active" mystery: the public
`*.apps.demo.hosted` endpoints sit behind **Cloudflare, which bans
python-urllib's default User-Agent with 403 error 1010 before auth is
evaluated**. The API key was valid the whole time; the poll loop also
swallowed every status invisibly. Proven by the paired diagnostics above
(same request: default UA → 1010; curl UA + key → 200 chat completion).
This also corrects round-2's "task pods are always 403'd at the public
gateway" theory. Fixes, all in `shared/llm_client.py`:

1. real `User-Agent` on every request;
2. `resolve_teacher_candidates`: svc DNS first in-cluster (WAF-free fast
   path), public+key as fallback and as the off-cluster path;
3. `wait_until_ready` mirrors llm-service's own smoke tests — poll
   `/health`, tolerate 502/503/504 during wake, record every candidate's
   per-poll status, and stream it into the task's live report.

Diagnostic kept: `probe_public_teacher.py`.
